# Professional PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the existing Vite + Phaser game into an installable, offline-capable, production-grade PWA.

**Architecture:** Keep the current Vite/Phaser structure intact. Add standards-based PWA assets under `public/`, register the service worker from `src/main.ts`, and use conservative cache strategies that work with Vite's hashed build output and game data files.

**Tech Stack:** TypeScript, Vite 5, Phaser 3, Web App Manifest, browser Service Worker API, Cache Storage API.

## Global Constraints

- Preserve the current package manager and scripts: npm, `npm run build`, `npm run typecheck`.
- Do not add a PWA plugin dependency; a hand-authored service worker is small and predictable for this game.
- Keep the app deployable under relative paths because `vite.config.ts` uses `base: './'`.
- Cache immutable hashed build assets aggressively; keep HTML/network entrypoints fresh.
- Support mobile install surfaces with manifest metadata, theme colors, apple touch metadata, and safe-area display settings.
- There is no Git repository in this workspace, so commit steps are intentionally omitted.

### Task 3: Service worker runtime

**Files:**
- Create: `public/sw.js`

**Interfaces:**
- Consumes: `manifest.webmanifest`, `offline.html`, Vite production assets, and `assets/data/*.json`.
- Produces: offline shell, precached static files, stale-while-revalidate runtime caching, explicit versioned caches, install activation cleanup.

- [ ] **Step 1: Implement cache constants**

Use versioned cache names such as `pixel-city-precache-v1` and `pixel-city-runtime-v1`.

- [ ] **Step 2: Implement install and activate handlers**

Precache the app shell and PWA assets; remove old caches during activation.

- [ ] **Step 3: Implement fetch strategy**

Use network-first for navigation, cache-first for hashed `/assets/` build files, and stale-while-revalidate for public game data and same-origin runtime requests.

- [ ] **Step 4: Add lifecycle message hooks**

Support `SKIP_WAITING` so a future in-app update prompt can activate a new worker immediately.
